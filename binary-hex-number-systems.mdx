You copy a line such as `PORTB = 0x3F;` from an example, a pin does the wrong thing, and you cannot find the fault because you cannot read the number. That number is a row of switches: it sets six bits high and two bits low. This lesson teaches you to read binary and hexadecimal, so that a value written to a microcontroller stops being a code you copy and becomes a bit pattern you chose. #Binary #Hexadecimal #NumberSystems

## Why Number Systems Matter for Embedded Programming

A microcontroller is set up through registers. A register is a small memory location in which each bit switches one hardware feature on or off. Consider this line of STM32 code:

```c
GPIOA->CRL = 0x44444443;
```

This one hexadecimal value sets up eight GPIO pins (general-purpose input/output pins). Each hex digit is 4 bits and controls the mode of one pin. Once you can read hex, the line says: "Pin 0 is an output, pins 1 through 7 are inputs."

You need three number systems:

| Base | Name | Digits Used | Prefix in C | Common Use |
|------|------|-------------|-------------|------------|
| 2 | Binary | 0, 1 | `0b` | Individual bit manipulation |
| 10 | Decimal | 0-9 | (none) | Human-readable values |
| 16 | Hexadecimal | 0-9, A-F | `0x` | Register values, addresses |

## Binary: The Language of Hardware

<InArticleAd />


### Counting in Binary

A wire in a digital circuit is low or high, so hardware counts with two digits: 0 and 1. One binary digit is a bit. In decimal, each position is worth ten times the position to its right. In binary, it is worth two times. The leftmost bit is the most significant bit (MSB) and the rightmost is the least significant bit (LSB).

```text
  8-bit Register (one byte)
  ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
  │ Bit7│ Bit6│ Bit5│ Bit4│ Bit3│ Bit2│ Bit1│ Bit0│
  │  1  │  0  │  1  │  1  │  0  │  0  │  1  │  1  │
  └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
   128    64    32    16     8     4     2     1
   (MSB)                                     (LSB)

  Value = 128 + 32 + 16 + 2 + 1 = 179
```

The weight of bit $n$ is $2^n$: bit 0 is worth 1 and bit 7 is worth $2^7 = 128$. To find the decimal value of a binary number, multiply each bit by its weight and add the results.

**Example:** `0b10110011`

$$
1 \times 128 + 0 \times 64 + 1 \times 32 + 1 \times 16 + 0 \times 8 + 0 \times 4 + 1 \times 2 + 1 \times 1 = 179
$$

### Counting from 0 to 15 in Binary

| Decimal | Binary (4-bit) | Decimal | Binary (4-bit) |
|---------|----------------|---------|----------------|
| 0 | 0000 | 8 | 1000 |
| 1 | 0001 | 9 | 1001 |
| 2 | 0010 | 10 | 1010 |
| 3 | 0011 | 11 | 1011 |
| 4 | 0100 | 12 | 1100 |
| 5 | 0101 | 13 | 1101 |
| 6 | 0110 | 14 | 1110 |
| 7 | 0111 | 15 | 1111 |

Notice the pattern: bit 0 changes on every count, bit 1 every 2 counts, bit 2 every 4 counts, and bit 3 every 8 counts. A binary counter circuit, which you build from flip-flops later in this course, works the same way.

### Powers of Two You Should Memorize

These values set the limits of the hardware you will use (ADC means analog-to-digital converter):

| Power | Value | Significance |
|-------|-------|-------------|
| $2^8$ | 256 | One byte range (0 to 255) |
| $2^{10}$ | 1,024 | 1 KB (kilobyte) |
| $2^{12}$ | 4,096 | 12-bit ADC range (0 to 4095) |
| $2^{16}$ | 65,536 | 16-bit timer range, 64 KB |
| $2^{20}$ | 1,048,576 | 1 MB |
| $2^{32}$ | 4,294,967,296 | 32-bit address space (4 GB) |

### Byte and Word Storage in Memory

Each memory address holds one byte, so a 32-bit value takes four addresses in a row. The bytes are not stored in the order you write them. In the order called little-endian, the lowest byte goes to the lowest address. You need this when you read a memory dump or join bytes that arrive from a sensor:

```text
  Memory layout: 32-bit value 0x12345678

  Address    Byte (little-endian)
  ┌────────┬──────────┐
  │ 0x1000 │   0x78   │  (LSB stored first)
  ├────────┼──────────┤
  │ 0x1001 │   0x56   │
  ├────────┼──────────┤
  │ 0x1002 │   0x34   │
  ├────────┼──────────┤
  │ 0x1003 │   0x12   │  (MSB stored last)
  └────────┴──────────┘

  ARM Cortex-M uses little-endian byte order.
```

### Converting Decimal to Binary

<Steps>
1. **Divide** the decimal number by 2.
2. **Record** the remainder (0 or 1). This is the next bit, starting from the least significant.
3. **Repeat** with the quotient until it reaches 0.
4. **Read** the remainders from bottom to top.
</Steps>

**Example:** Convert 179 to binary.

| Step | Division | Quotient | Remainder |
|------|----------|----------|-----------|
| 1 | 179 / 2 | 89 | 1 (bit 0) |
| 2 | 89 / 2 | 44 | 1 (bit 1) |
| 3 | 44 / 2 | 22 | 0 (bit 2) |
| 4 | 22 / 2 | 11 | 0 (bit 3) |
| 5 | 11 / 2 | 5 | 1 (bit 4) |
| 6 | 5 / 2 | 2 | 1 (bit 5) |
| 7 | 2 / 2 | 1 | 0 (bit 6) |
| 8 | 1 / 2 | 0 | 1 (bit 7) |

Reading remainders bottom to top: **10110011**. Verify: $128 + 32 + 16 + 2 + 1 = 179$.

## Hexadecimal: Compact Binary

<InArticleAd />


### Why Hex?

Binary is exact but long. Nobody can check `0b11111111111111111111111111111111` by eye. Hexadecimal (base 16) writes every group of 4 bits as one digit. Base 16 needs sixteen digits, so after 9 it uses the letters A to F for the values 10 to 15:

| Hex Digit | Binary | Decimal |
|-----------|--------|---------|
| 0 | 0000 | 0 |
| 1 | 0001 | 1 |
| 2 | 0010 | 2 |
| 3 | 0011 | 3 |
| 4 | 0100 | 4 |
| 5 | 0101 | 5 |
| 6 | 0110 | 6 |
| 7 | 0111 | 7 |
| 8 | 1000 | 8 |
| 9 | 1001 | 9 |
| A | 1010 | 10 |
| B | 1011 | 11 |
| C | 1100 | 12 |
| D | 1101 | 13 |
| E | 1110 | 14 |
| F | 1111 | 15 |

One hex digit = 4 bits. Two hex digits = 8 bits (one byte). Eight hex digits = 32 bits (one word on ARM Cortex-M).

### Hex to Binary (and Back)

No arithmetic is needed. Replace each hex digit with its 4 bits from the table:

**Example:** `0x3F` to binary

- `3` = `0011`
- `F` = `1111`
- Result: `0b00111111`

**Example:** `0b10110011` to hex

- Split into groups of 4 from the right: `1011` `0011`
- `1011` = B
- `0011` = 3
- Result: `0xB3`

### Hex to Decimal

Each position is worth 16 times the position to its right. Multiply each hex digit by the weight of its position and add:

**Example:** `0x3F`

$$
3 \times 16^1 + 15 \times 16^0 = 48 + 15 = 63
$$

You almost never convert a long hex value such as the address `0x40021000` to decimal. You work in hex because the bit grouping is what matters.

### Reading Register Values in Hex

Programs, variables and registers all have addresses. The first hex digits of an address tell you its region:

```text
  MCU Memory Address Map (simplified)
  ┌────────────────────────┐ 0xFFFFFFFF
  │   System / Cortex-M    │
  ├────────────────────────┤ 0xE0000000
  │       (reserved)       │
  ├────────────────────────┤ 0x40000000
  │   Peripheral Regs      │
  │   (GPIO, UART, SPI...) │
  ├────────────────────────┤ 0x20000000
  │   SRAM (variables)     │
  ├────────────────────────┤ 0x08000000
  │   Flash (program code) │
  └────────────────────────┘ 0x00000000
```

Here is a real example. On the STM32F103, the register that sets up pins 0 to 7 of port A (GPIOA_CRL) is at address `0x40010800` and might contain:

```
GPIOA->CRL = 0x44444443
```

Break it into nibbles (a nibble is a group of 4 bits, one hex digit), one per pin. PA0 means port A, pin 0. Read the table from the rightmost digit:

| Hex Digit | Binary | Pin | Meaning |
|-----------|--------|-----|---------|
| 3 | 0011 | PA0 | Output, push-pull, 50 MHz |
| 4 (seven times) | 0100 | PA1 to PA7 | Floating input |

The least significant hex digit belongs to the lowest pin number. Each nibble holds the mode of one pin and its electrical type (push-pull, floating). You meet those types when you program the chip. Here only the reading matters.

## Binary Coded Decimal (BCD)

<InArticleAd />


### What Is BCD?

A clock or a meter shows decimal digits. Pure binary makes that awkward: to show 47, the chip must first divide by ten. Binary coded decimal (BCD) avoids the division. It stores each decimal digit on its own, in 4 bits:

| Decimal | BCD |
|---------|-----|
| 0 | 0000 |
| 1 | 0001 |
| 2 | 0010 |
| ... | ... |
| 9 | 1001 |

The patterns 1010 through 1111 are not used in BCD. That wastes some patterns, but each group of 4 bits can go straight to one digit of a display.

**Example:** Decimal 47 in BCD

- 4 = `0100`
- 7 = `0111`
- BCD: `0100 0111`

Compare with pure binary: 47 in binary is `00101111`. The two patterns differ, so you must know which one a chip uses before you read its value. A useful sign: written in hex, a BCD value shows its decimal digits (`0x47`).

### Where BCD Appears in Embedded Systems

- Real-time clock (RTC) chips: the DS3231 and the STM32 internal RTC store time in BCD. If the hours register reads `0x23`, the time is 23 hours, not decimal 35.
- Seven-segment display drivers: decoder chips such as the 74LS47 take a 4-bit BCD input and drive the segments of one digit.

### BCD Conversion in C

```c
// Convert binary to BCD (for values 0-99)
uint8_t binary_to_bcd(uint8_t binary) {
    return ((binary / 10) << 4) | (binary % 10);
}

// Convert BCD to binary
uint8_t bcd_to_binary(uint8_t bcd) {
    return ((bcd >> 4) * 10) + (bcd & 0x0F);
}
```

When reading time from an RTC:

```c
uint8_t hours_bcd = rtc_read(RTC_HOURS_REG);  // Returns 0x23
uint8_t hours = bcd_to_binary(hours_bcd);       // Returns 23
```

## Signed Integers: Two's Complement

<InArticleAd />


### The Problem with Unsigned Numbers

An 8-bit unsigned integer holds values from 0 to 255. It has no minus sign. But a temperature can be below zero, and a motor can turn backward. Hardware needs a way to write a negative number with only ones and zeros.

### Two's Complement Representation

Two's complement is the standard way. Think of a car's distance counter at 0000. Drive backward one kilometre and it shows 9999, so 9999 can stand for -1. In binary, one step below `0000 0000` is `1111 1111`, and that pattern stands for -1. The upper half of the patterns holds the negative numbers, so the MSB tells the sign:

- **MSB = 0**: the number is positive (or zero)
- **MSB = 1**: the number is negative

For an 8-bit signed integer:

| Binary | Unsigned Value | Signed Value (Two's Complement) |
|--------|---------------|-------------------------------|
| 0111 1111 | 127 | +127 |
| 0000 0001 | 1 | +1 |
| 0000 0000 | 0 | 0 |
| 1111 1111 | 255 | -1 |
| 1111 1110 | 254 | -2 |
| 1000 0001 | 129 | -127 |
| 1000 0000 | 128 | -128 |

An 8-bit signed integer ranges from -128 to +127. For a pattern whose MSB is 1, the signed value is the unsigned value minus 256: 255 - 256 = -1.

### Finding the Two's Complement

To change the sign of a number in two's complement:

<Steps>
1. **Invert** all bits (change 0 to 1 and 1 to 0). This is called the one's complement.
2. **Add 1** to the result.
</Steps>

**Example:** Find the two's complement representation of -5.

1. Start with +5: `0000 0101`
2. Invert all bits: `1111 1010`
3. Add 1: `1111 1011`

Check: `1111 1011` is 251 unsigned, and 251 - 256 = -5.

### Why Two's Complement Works

With two's complement, addition is the same operation for signed and unsigned numbers. The hardware does not need a second adder circuit:

```
   0000 0011   (+3)
+  1111 1011   (-5)
-----------
   1111 1110   (-2)  ✓
```

Any carry out of the MSB is discarded. This is why the arithmetic logic unit (ALU), the part of the processor that calculates, uses one adder for both signed and unsigned arithmetic.

### Two's Complement in C

The bits do not say whether they are signed. The type you give the variable decides. In C, `int8_t` is a signed 8-bit type and `uint8_t` is unsigned:

```c
uint8_t a = 0xFB;   // Unsigned: 251
int8_t  b = 0xFB;   // Signed: -5 (same bits, different interpretation)

printf("Unsigned: %u\n", a);  // Prints 251
printf("Signed: %d\n", b);    // Prints -5
```

This matters when you read sensor data. An accelerometer might return a signed 16-bit value where `0xFFE0` means -32, not 65,504. With 4 bits, the sixteen patterns are shared like this:

```text
  4-bit patterns read as signed numbers

  1000  1001  ...  1111 │ 0000  0001  ...  0111
   -8    -7   ...   -1  │   0    +1   ...   +7
  most                  │                  most
  negative             zero            positive
```

### Sign Extension

When you move a signed value from a smaller type to a larger type, the new upper bits must be copies of the sign bit. If they were filled with zeros, -5 would turn into +251. This is called sign extension:

```c
int8_t  small = -5;      // 0xFB = 1111 1011
int16_t large = small;    // 0xFFFB = 1111 1111 1111 1011
```

The compiler does this for you when you assign between signed types.

## Bit Manipulation: The Bridge to Hardware

<InArticleAd />


### Bitwise Operators in C

One register controls many things, one per bit. To change one of them you must change one bit and leave the others as they are. The bitwise operators do this, one bit position at a time. Each matches a logic gate from the next lesson:

| Operator | Name | Example | Result | Gate Equivalent |
|----------|------|---------|--------|-----------------|
| `&` | AND | `0xF0 & 0x3C` | `0x30` | AND gate |
| `\|` | OR | `0xF0 \| 0x3C` | `0xFC` | OR gate |
| `^` | XOR | `0xF0 ^ 0x3C` | `0xCC` | XOR gate |
| `~` | NOT | `~0xF0` | `0x0F` | NOT gate (inverter) |
| `<<` | Left shift | `0x01 << 3` | `0x08` | Shift register |
| `>>` | Right shift | `0x80 >> 3` | `0x10` | Shift register |

### Common Bit Manipulation Patterns

Every pattern starts with a mask: a number that has a 1 only at the bits you want to touch. `(1 << 5)` moves a single 1 five places to the left, so it is the mask for bit 5.

**Set a bit** (turn it to 1 without changing other bits). OR with 1 gives 1, and OR with 0 leaves a bit as it was:

```c
PORTB |= (1 << 5);   // Set bit 5 of PORTB
```

```text
  bit         7 6 5 4 3 2 1 0
  PORTB       1 1 0 0 0 0 0 1    0xC1  before
  (1 << 5)    0 0 1 0 0 0 0 0    0x20  mask
  OR result   1 1 1 0 0 0 0 1    0xE1  after
```

**Clear a bit** (turn it to 0 without changing other bits). The `~` inverts the mask, so it has a 0 only at bit 5. AND with 0 gives 0, and AND with 1 leaves a bit as it was:

```c
PORTB &= ~(1 << 5);  // Clear bit 5 of PORTB
```

**Toggle a bit** (flip its value):

```c
PORTB ^= (1 << 5);   // Toggle bit 5 of PORTB
```

**Check a bit** (test if it is set):

```c
if (PINB & (1 << 5)) {
    // Bit 5 is high
}
```

**Set multiple bits using a mask:**

```c
// Set bits 0, 1, and 5 of a control register
CTRL_REG |= (1 << 0) | (1 << 1) | (1 << 5);  // 0x23
```

**Clear a field and set a new value:**

```c
// Set timer prescaler bits [2:0] to value 5, without changing other bits
TCCR0B = (TCCR0B & ~0x07) | 0x05;
```

Every pattern reads the register, changes only the masked bits, and writes the result back. A plain constant, as in `PORTB = 0x20;`, writes all eight bits and destroys the other seven settings.

### Exercise 2: Two's Complement

Find the 8-bit two's complement representation of these signed values:

1. -1
2. -128
3. -42
4. -100

<details>
<summary>**Solutions**</summary>

1. -1: invert `0000 0001` to `1111 1110`, add 1 = `1111 1111` = `0xFF`
2. -128: `1000 0000` = `0x80` (the most negative 8-bit signed value)
3. -42: invert `0010 1010` to `1101 0101`, add 1 = `1101 0110` = `0xD6`
4. -100: invert `0110 0100` to `1001 1011`, add 1 = `1001 1100` = `0x9C`

</details>

### Exercise 3: Decode a Register Value

An STM32 GPIO output data register (ODR) reads `0x00000A5F`. Which pins (0 through 15) are high?

<details>
<summary>**Solution**</summary>

Focus on the lower 16 bits: `0x0A5F`

Convert to binary: `0000 1010 0101 1111`

Number the bits from the right, starting at 0, and list the positions that hold a 1:

- `1111` (bits 3 to 0): pins 0, 1, 2, 3
- `0101` (bits 7 to 4): pins 4, 6
- `1010` (bits 11 to 8): pins 9, 11
- `0000` (bits 15 to 12): none

Pins high: 0, 1, 2, 3, 4, 6, 9, 11.

</details>

### Exercise 4: Bit Manipulation in C

Write C expressions to:

1. Set bits 4 and 7 of register `REG` without changing other bits.
2. Clear bits 0 through 3 of register `REG` without changing other bits.
3. Check if bit 5 of register `STATUS` is set.
4. Extract bits [7:4] from register `DATA` as a value from 0 to 15.

<details>
<summary>**Solutions**</summary>

```c
// 1. Set bits 4 and 7
REG |= (1 << 4) | (1 << 7);   // or: REG |= 0x90;

// 2. Clear bits 0-3
REG &= ~0x0F;                  // or: REG &= 0xFFFFFFF0;

// 3. Check bit 5
if (STATUS & (1 << 5)) { /* bit 5 is set */ }

// 4. Extract bits [7:4]
uint8_t value = (DATA >> 4) & 0x0F;
```

</details>
