A device loses its calibration every time the power fails. A program that worked for months stops when one more array fills the last bytes of RAM. A data logger wears out its storage in a week. Each fault comes from putting data in the wrong kind of memory. A microcontroller (MCU) has three kinds: SRAM, Flash and EEPROM. This lesson shows how each one stores a bit, what each one is good and bad at, and how the memory map gives every byte and every hardware register its own address. #Memory #SRAM #Flash

## Memory Classification

Volatile memory forgets its contents when the power is removed. Non-volatile memory keeps them, but it is slower to write and it wears out.

| Category | Retains Data Without Power? | Speed | Examples |
|----------|---------------------------|-------|---------|
| **Volatile** | No | Fast | SRAM, DRAM |
| **Non-volatile** | Yes | Slower | Flash, EEPROM, ROM |

A microcontroller uses each kind for a different job:

- SRAM holds variables while the program runs. It is fast, and its contents are lost at power-off.
- Flash holds the program and constant data. It is slow to write.
- EEPROM holds settings and calibration data. It changes one byte at a time.

| MCU | SRAM | Flash | EEPROM |
|-----|------|-------|--------|
| ATmega328P | 2 KB | 32 KB | 1 KB |
| STM32F103C8T6 (Blue Pill) | 20 KB | 64 KB | None (emulated in Flash) |
| ESP32 | 520 KB | 4 MB (external SPI Flash) | None (emulated in Flash) |
| RP2040 (Pico) | 264 KB | 2 MB (external QSPI Flash) | None |

## SRAM: Static Random Access Memory

<InArticleAd />


### The 6-Transistor Cell

Each bit in SRAM is stored by a circuit of six transistors, called a 6T cell. Four of them form two inverters (NOT gates), and the output of each inverter feeds the input of the other. If Q is 1, the first inverter makes Q' 0, and the second inverter turns that 0 back into the 1 at Q. The loop holds its own value, like the SR latch built from two cross-coupled gates. It holds it only while power is supplied.

```text
              word line (selects this cell)
       ──────┬──────────────────────┬──────
             │                      │
  BL ────[switch]─┬──►[NOT]──►──┬─[switch]──── BL'
                  Q             Q'
                  └──◄[NOT]◄────┘
```

The other two transistors are switches. When the word line is active, they connect the cell to the two bit lines, BL and BL'. To read, the CPU senses the bit lines. To write, it forces them to the new value, which overpowers the small inverters.

**Key properties of SRAM:**

| Property | Value |
|----------|-------|
| Read speed | 1 clock cycle (typically) |
| Write speed | 1 clock cycle |
| Endurance | Unlimited read/write cycles |
| Data retention | Only while powered |
| Cell size | 6 transistors per bit (relatively large) |
| Power | Consumes power continuously to maintain state |

### Why SRAM Is Used for Variables

When you write:

```c
int x = 42;
```

The compiler reserves space in SRAM for `x`. The CPU can read and write this location in a single clock cycle, and it can do so any number of times. Three things live in SRAM:

- global variables
- the stack, which holds local variables and the return addresses of function calls
- the heap, the area that `malloc` gives out while the program runs

An ATmega328P has only 2 KB, and one 512-byte buffer takes a quarter of it.

## Flash Memory

<InArticleAd />


### The Floating Gate Transistor

To keep a bit without power, something must stay in place when the supply is gone. Flash uses a transistor with one extra part, the floating gate: a small piece of conductor with insulating oxide on every side and no wire to it. Think of a sealed jar. Electric charge that is forced into the jar stays there for years, because it has no path out. The comparison stops here: every time charge is forced through the wall, the wall is damaged a little.

The stored charge changes the threshold voltage of the transistor, which is the gate voltage needed to switch it on.

1. **Programmed (storing 0):** A high voltage (around 10-20V, made inside the chip) forces electrons onto the floating gate. They raise the threshold voltage, so the transistor is harder to switch on.

2. **Erased (storing 1):** A voltage in the opposite direction removes the electrons. The threshold voltage returns to its normal level.

3. **Reading:** A normal read voltage is applied to the control gate. An erased cell conducts, and the bit reads as 1. A programmed cell does not conduct, and the bit reads as 0.

**Key properties of Flash:**

| Property | Value |
|----------|-------|
| Read speed | Fast (comparable to SRAM in many MCUs) |
| Write speed | Slow (microseconds to milliseconds per page) |
| Erase granularity | Page or sector (cannot erase single bytes) |
| Endurance | 10,000 to 100,000 erase/write cycles |
| Data retention | 10 to 20 years (specified by manufacturer) |

### NOR Flash vs NAND Flash

| Property | NOR Flash | NAND Flash |
|----------|-----------|------------|
| Read access | Random (byte-addressable) | Sequential (page-based) |
| Cost per bit | Higher | Lower |
| Used for | MCU program memory | USB drives, SD cards, SSDs |

The two types differ in how the cells are wired together. Most microcontrollers use NOR Flash for the program, because the CPU can read any byte directly and so can run code from Flash without copying it to RAM. The STM32F103C8 has 64 KB of NOR Flash for your compiled firmware.

### Flash Write Restrictions

Flash has two constraints that surprise people who think of it as slow RAM:

1. **Erase works on a whole page.** Flash is organized into pages (typically 1-4 KB on MCUs). Erasing sets every bit of the page to 1.

2. **Programming only changes a 1 to a 0.** To change one 0 back to 1, you must erase the entire page and write all of it again.

This is why a firmware update takes time: the bootloader, the small program that receives new firmware, must erase each Flash page before it writes. Each erase also wears the page a little.
## EEPROM: Electrically Erasable Programmable ROM

<InArticleAd />


### How EEPROM Differs from Flash

EEPROM uses the same floating gate as Flash, with one difference: EEPROM can erase and write a single byte, while Flash must erase a whole page.

This suits small amounts of data that change now and then: calibration values, device IDs, user settings.

**Key properties of EEPROM:**

| Property | Value |
|----------|-------|
| Read speed | Fast |
| Write speed | Slow (3-5 ms per byte, typically) |
| Erase granularity | Single byte |
| Endurance | 100,000 to 1,000,000 write cycles |
| Data retention | 20+ years |

### EEPROM in MCUs

The ATmega328P has 1 KB of EEPROM. An external EEPROM chip such as the 24C256 adds 32 KB to any MCU. The STM32F103 has no EEPROM. ST provides an "EEPROM emulation" library that uses two Flash pages in its place. Each new value is written to the next free space in a page. When the page is full, the latest values are copied to the other page, and the full page is erased.

### Wear Leveling

A cell that lasts 100,000 writes sounds safe, but a program can use them quickly. A loop that writes one address again and again, at about 3.3 ms per write, uses 100,000 writes in under 6 minutes. Wear leveling spreads the writes over many addresses, so each cell receives only a share of them.

```c
// BAD: writes to the same address every loop iteration
while (1) {
    eeprom_write(0x00, sensor_value);  // Will wear out address 0x00
    delay_ms(10);
}

// BETTER: rotate through multiple addresses
uint16_t write_index = 0;
while (1) {
    eeprom_write(write_index, sensor_value);
    write_index = (write_index + 1) % EEPROM_SIZE;
    delay_ms(10);
}
```

**Check it: count the writes.** The BETTER loop still writes every 13.3 ms (10 ms of delay plus 3.3 ms of write), about 75 times a second. Spread over 1024 addresses of 100,000 writes each, the EEPROM lasts $1024 \times 100{,}000 / 75 \approx 1.4$ million seconds: about 16 days. Rotation buys time; writing less often solves the problem. Save when the value has changed by more than a set step, or every 10 minutes: one address then lasts about 1.9 years, and a rotation over 1024 outlasts the product. Give each entry a sequence number, so that after a reset the program can find the newest.

## Address Bus, Data Bus, and Control Signals

<InArticleAd />


### Bus Basics

The CPU must tell memory which byte it wants, and then move the data. It does both through buses: groups of parallel wires shared by the CPU, the memories and the peripherals (the hardware blocks, such as timers and pin drivers, built into the chip).

```text
  ┌───────┐                        ┌────────┐
  │       │══ Address [31:0] ═════►│        │
  │  CPU  │                        │ Memory │
  │       │◄═ Data [31:0] ════════►│  or    │
  │       │                        │Periph. │
  │       │── RD / WR ────────────►│        │
  │       │── Chip Select ────────►│        │
  └───────┘                        └────────┘
```

| Bus | Function | Width (STM32F103) |
|-----|----------|-------------------|
| **Address bus** | Specifies which memory location to access | 32 bits (4 GB addressable) |
| **Data bus** | Carries the data being read or written | 32 bits |
| **Control bus** | Read/write signal, clock, chip select | Several individual signals |

### A Memory Read Cycle

The C line `x = *((volatile uint32_t *)0x40021000);` means "read the 32-bit value at address `0x40021000` and put it in `x`". The CPU does it in these steps:

<Steps>
1. The CPU places the address `0x40021000` on the address bus.
2. The CPU makes the READ signal active on the control bus.
3. The address decoder, a combinational circuit that turns an address into one enable line, selects the device that must answer. This address belongs to a peripheral: the RCC block, which controls the clocks.
4. The selected device places the requested 32-bit data on the data bus.
5. The CPU captures the data from the data bus in an internal register.
6. The value is stored in the variable `x` (in SRAM).
</Steps>

For SRAM and Flash this takes one or two clock cycles. A slower device asks the CPU to wait for extra cycles, called wait states.

### A Memory Write Cycle

The line `*((volatile uint32_t *)0x40021000) = 0x00000001;` writes the value 1 to the same address:

<Steps>
1. The CPU places `0x40021000` on the address bus.
2. The CPU places `0x00000001` on the data bus.
3. The CPU makes the WRITE signal active.
4. The address decoder enables the RCC block.
5. The RCC block captures the data from the data bus in the register at that address.
</Steps>

## Memory Maps

<InArticleAd />


### What Is a Memory Map?

A 32-bit address bus can name about 4 billion bytes (0x00000000 to 0xFFFFFFFF). The chip has far less than that, so most addresses are empty. The memory map is the plan that says which range of addresses belongs to which device, as a street plan says which house numbers belong to which building. Here is the map of the STM32F103C8, with the lowest address at the bottom:

```text
  0xFFFFFFFF ┌─────────────────────────────┐
             │ Cortex-M3 internals         │
  0xE0000000 ├─────────────────────────────┤
             │     (reserved)              │
  0x40024000 ├─────────────────────────────┤
             │ Peripheral registers        │
  0x40000000 ├─────────────────────────────┤
             │     (reserved)              │
  0x20005000 ├─────────────────────────────┤
             │ SRAM 20 KB: variables, stack│
  0x20000000 ├─────────────────────────────┤
             │     (reserved)              │
  0x08010000 ├─────────────────────────────┤
             │ Flash 64 KB: program, const │
  0x08000000 └─────────────────────────────┘
```

The size of a region follows from its range: 0x08000000 to 0x0800FFFF is 0x10000 addresses, which is 65,536 bytes or 64 KB. When the chip starts from Flash, the same Flash also appears at address 0x00000000. A second range that reaches the same memory is called an alias.

### How the Memory Map Enables Memory-Mapped I/O

The peripheral region holds no memory chip. Its addresses lead to registers: small groups of flip-flops whose outputs control hardware, such as a GPIO (general purpose input/output) pin. This is memory-mapped I/O. You control a pin the same way you change a variable in SRAM: by writing to an address.

```c
// This writes to SRAM (a variable)
uint32_t x = 42;

// This writes to a GPIO peripheral register (same syntax, different address)
*((volatile uint32_t *)0x4001080C) = 0x0001;  // GPIOA output data register
```

The CPU does not know whether the address leads to SRAM, Flash or a peripheral. It puts the address on the bus, and the decoder selects the right device. So the CPU needs no special instructions for hardware.

### The ATmega328P Memory Map

The data memory of the ATmega328P has the same structure on a smaller scale. Its program Flash has a separate address space.

| Address Range | Size | Device |
|--------------|------|--------|
| 0x0000 to 0x001F | 32 bytes | CPU registers (R0-R31) |
| 0x0020 to 0x005F | 64 bytes | I/O registers (PORTB, DDRB, etc.) |
| 0x0060 to 0x00FF | 160 bytes | Extended I/O registers |
| 0x0100 to 0x08FF | 2 KB | SRAM |

When you write `PORTB = 0xFF;`, the compiler writes to PORTB, which sits at data address 0x25. Because PORTB is in the first 64 I/O registers, it uses the short `out` instruction with the I/O address 0x05 (0x25 minus the 0x20 of the CPU registers).

## The `volatile` Keyword and Memory Access

<InArticleAd />


### Why `volatile` Matters

A compiler makes code faster by removing work that looks useless. If your program reads the same address twice and writes nothing between, the compiler assumes the value is the same and reads once. For a variable that is correct. For a hardware register it is wrong, because the hardware changes the value by itself. (The C word `volatile` has nothing to do with volatile memory.)

```c
volatile uint32_t *gpio_odr = (volatile uint32_t *)0x4001080C;
*gpio_odr = 0x0001;  // Turn on pin 0
```

Without `volatile`, the compiler may:

1. keep the value in a CPU register and never write it to the peripheral
2. remove a write that is followed by another write to the same address

The `volatile` keyword tells the compiler: "Hardware can change this location at any time. Every read and write in the code must really happen, in order."

### Example: Polling a Status Register

The loop below polls: it reads a status register again and again until bit 6 (`0x40`) becomes 1.

```c
// WITHOUT volatile (BUG: may loop forever)
uint32_t *status = (uint32_t *)0x40013800;
while (!(*status & 0x40)) { }  // Compiler may read once and cache

// WITH volatile (CORRECT)
volatile uint32_t *status = (volatile uint32_t *)0x40013800;
while (!(*status & 0x40)) { }  // Compiler reads from hardware every iteration
```

`volatile` fixes the compiler, not the hardware. If the peripheral never sets the bit (its clock is not enabled, a cable is cut), this loop still waits for ever, and the device stops. In a product, give every such loop a limit and handle the failure:

```c
uint32_t tries = 100000;
while (!(*status & 0x40) && --tries) { }
if (tries == 0) {
    // the bit never came: report an error, reset the peripheral, do not hang
}
```

## Exercises

<InArticleAd />


### Exercise 1: Memory Sizing

An MCU has a 16-bit address bus and an 8-bit data bus. What is the maximum addressable memory? How many SRAM cells (6T cells) would be needed to fill the entire address space?

<details>
<summary>**Solution**</summary>

Maximum addressable memory: $2^{16} = 65{,}536$ bytes = 64 KB.

Each byte requires 8 bits of storage. Each bit requires one 6T SRAM cell.

Total cells: $65{,}536 \times 8 = 524{,}288$ cells, each using 6 transistors: $524{,}288 \times 6 = 3{,}145{,}728$ transistors.

</details>

### Exercise 2: Flash Page Erase

You have a device with 1 KB Flash pages. The page at address 0x08002000 currently contains your calibration data at offset 0x10 (address 0x08002010). You need to update one byte at that offset. What steps must you take?

<details>
<summary>**Solution**</summary>

1. Read the entire 1 KB page (0x08002000 to 0x080023FF) into an SRAM buffer.
2. Modify the byte at offset 0x10 in the buffer.
3. Erase the Flash page (sets all 1024 bytes to 0xFF).
4. Write the modified buffer back to the Flash page.

This read-modify-write cycle is why Flash writes are slow and why EEPROM (or EEPROM emulation) is preferred for frequently changing data. It also has a risk: if the power fails between steps 3 and 4, the page is blank and the calibration is lost. EEPROM emulation avoids this by writing the new copy to a second page before it erases the old one.

</details>

### Exercise 3: Memory Map Decoding

On an STM32F103, you read address `0x40010C0C`. Based on the memory map, what type of device does this access? (Hint: 0x40000000 is the peripheral base, and GPIO Port B starts at 0x40010C00.)

<details>
<summary>**Solution**</summary>

Address 0x40010C0C falls in the peripheral region (0x40000000 and above). GPIOB base is 0x40010C00. The offset is 0x0C, which is the GPIO Output Data Register (ODR) for Port B.

So reading or writing this address accesses GPIOB_ODR, which controls the output state of pins PB0 through PB15.

```c
// This sets PB0 high and all others low:
*((volatile uint32_t *)0x40010C0C) = 0x0001;
```

</details>

## Summary

<InArticleAd />


| Memory Type | Volatile? | Write Granularity | Endurance | Typical Use |
|-------------|-----------|-------------------|-----------|-------------|
| SRAM | Yes | Byte/word, unlimited | Unlimited | Variables, stack, heap |
| Flash | No | Page erase, then write | 10K-100K cycles | Program code, constant data |
| EEPROM | No | Single byte | 100K-1M cycles | Configuration, calibration |

The memory map gives Flash, SRAM and every peripheral register a range of addresses, and `volatile` makes the compiler perform every access to a register.

The buses in this lesson stay inside the chip. SPI, I2C and UART are the buses that leave it, to reach sensors and other devices.
