A tank level reading changes by three counts when nothing has moved. A vibration log shows a slow wave that no machine makes. A pressure sensor changes by half a millivolt and the reading does not change at all. None of these is a fault in your code. They come from the way a voltage becomes a number. An ADC (analog-to-digital converter) turns a voltage into a number, and a DAC (digital-to-analog converter) does the opposite. This lesson shows how both work, so that you can choose the resolution, the sample rate and the filter your measurement needs. #ADC #DAC #SignalConversion

## ADC Fundamentals

### What an ADC Does

An analog voltage can have any value. A digital number is one of a fixed set. An ADC measures a voltage as you measure a length with a ruler marked only in millimetres: you read a mark, and what lies between two marks is lost. It works in two steps:

1. **Sampling:** it captures the voltage at one instant.
2. **Quantization:** it replaces the captured voltage by one of its fixed levels.

### Resolution

Resolution is the number of bits in the ADC's output. With $n$ bits there are $2^n$ levels, the marks on the ruler.

| ADC Resolution | Number of Levels | Typical MCU |
|----------------|-----------------|-------------|
| 8-bit | 256 | ATmega328P, when only the top 8 bits are read |
| 10-bit | 1,024 | ATmega328P |
| 12-bit | 4,096 | STM32F103, STM32F4, ESP32 |
| 16-bit | 65,536 | Some STM32H7 variants, external ADCs |
| 24-bit | 16,777,216 | External ADCs (ADS1256 for precision measurement) |

### Least Significant Bit (LSB) Voltage

The ADC divides the range from 0 V to its reference voltage $V_{ref}$ into $2^n$ equal steps, where $n$ is the resolution in bits. The size of one step is the LSB voltage, the distance between two marks on the ruler. (When the input rises by one step, the least significant bit of the output changes.)

$$V_{LSB} = \frac{V_{ref}}{2^n}$$

**Example:** A 12-bit ADC with $V_{ref} = 3.3\text{V}$:

$$V_{LSB} = \frac{3.3}{2^{12}} = \frac{3.3}{4096} \approx 0.806 \text{ mV}$$

A change smaller than 0.8 mV can stay inside one step, and then the reading does not change.

:::note[4096 or 4095?]
A 12-bit ADC has 4096 steps, so the step is $V_{ref} / 4096$. The codes are numbered from 0, so the largest code is 4095. It means $4095 \times 3.3 / 4096 = 3.2992\text{V}$, one step below $V_{ref}$. To convert a code to a voltage, divide by 4096.
:::

### ADC Transfer Function

The output code is the input as a fraction of $V_{ref}$, multiplied by the number of steps and rounded down (the brackets $\lfloor \; \rfloor$ mean "round down"):

$$\text{Digital Code} = \left\lfloor \frac{V_{in}}{V_{ref}} \times 2^n \right\rfloor$$

**Example:** What digital code does a 12-bit ADC (3.3V reference) produce for an input of 1.65V?

$$\text{Code} = \left\lfloor \frac{1.65}{3.3} \times 4096 \right\rfloor = \left\lfloor 2048 \right\rfloor = 2048$$

To convert back from a digital code to voltage:

$$V_{in} = \frac{\text{Code} \times V_{ref}}{2^n}$$

In C:

```c
// STM32 12-bit ADC, 3.3V reference
uint16_t adc_value = HAL_ADC_GetValue(&hadc1);
float voltage = (float)adc_value * 3.3f / 4096.0f;
```

`HAL_ADC_GetValue` only returns the last result. In a program, start a conversion, wait with a time limit, and use the value only if it arrived:

```c
HAL_ADC_Start(&hadc1);
if (HAL_ADC_PollForConversion(&hadc1, 10) == HAL_OK) {   // wait at most 10 ms
    uint16_t adc_value = HAL_ADC_GetValue(&hadc1);
    float voltage = (float)adc_value * 3.3f / 4096.0f;
} else {
    // no new result: report it, do not reuse the old value
}
```

The `3.3f` assumes the reference is exactly 3.3V. On the STM32F103C8 the reference is the analog supply, so a regulator at 3.25V makes every reading 1.5 % low. **Check it:** put the supply voltage you measure with a meter in the code, then compare a known input voltage with the computed one.

### Quantization Error

The input can be anywhere inside a step, but the code names only the step. The difference is the quantization error. When each code is taken to mean the middle of its step, the error is at most $\pm \frac{1}{2}$ LSB.

For a 12-bit ADC with 3.3V reference:

$$\text{Max quantization error} = \pm \frac{V_{LSB}}{2} = \pm 0.403 \text{ mV}$$

One reading cannot show anything finer. For smaller steps you need an ADC with more bits.

### Other ADC Error Sources

A real ADC adds more errors, usually larger ones:

| Error | Description | Typical Magnitude |
|-------|-------------|-------------------|
| Offset error | Output is not zero when input is 0V | 1-2 LSB |
| Gain error | Every reading is wrong by the same percentage | 1-5 LSB |
| Nonlinearity (INL, DNL) | Some steps are wider than others | 0.5-3 LSB |
| Noise | Random variation in readings | 1-3 LSB (depends on layout, decoupling) |

In most embedded work the largest error is noise. A capacitor close to the supply pin of the ADC (decoupling) and averaging in software both reduce it.

## Successive Approximation ADC (SAR)

<InArticleAd />


### How It Works

The SAR ADC is the most common type in microcontrollers. It works like a balance with weights of 8, 4, 2 and 1. You try the largest weight first. If it is too heavy you remove it, if not you keep it, and you try the next one. Four tries give the answer. This is a binary search.

In the ADC the parts are:

- a sample-and-hold circuit (S/H), which keeps the input steady during the search
- an internal DAC, which makes the trial voltage (the weights)
- a comparator, which says which of two voltages is higher (the balance)
- the SAR (successive approximation register), which holds the bits decided so far

```text
  Vin ──→[S/H]──→(+)─┐
                      │ Comparator
  Vref ──→[DAC]──→(-)─┘
              ▲           │
              │       ┌───┴────┐
              │       │  SAR   │
              └───────┤Control │
                      │Register│
                      └───┬────┘
                          │
                     Digital Output
                      (n-bit code)
```

**Process for a 4-bit SAR ADC (simplified):**

<Steps>
1. **Sample and hold:** The input voltage is captured and held steady on a capacitor.

2. **Bit 3 test:** Bit 3 is the most significant bit (MSB). Set the DAC to 1000 (half of full scale). Is the input greater than the DAC output? If yes, keep bit 3 as 1. If no, set bit 3 to 0.

3. **Bits 2, 1 and 0:** For each bit in turn, set it to 1 on top of the result so far (adding 0100, then 0010, then 0001), compare, and keep or clear it.

4. **Result:** The 4-bit code in the SAR is the highest code whose voltage is below the input.
</Steps>

**Example: Converting 2.1V with a 4-bit ADC, 3.3V reference**

| Step | Test Value | DAC Voltage | Compare | Bit Value | SAR Register |
|------|-----------|-------------|---------|-----------|-------------|
| 1 | 1000 | 1.65V | 2.1 > 1.65: yes | 1 | 1000 |
| 2 | 1100 | 2.475V | 2.1 > 2.475: no | 0 | 1000 |
| 3 | 1010 | 2.0625V | 2.1 > 2.0625: yes | 1 | 1010 |
| 4 | 1011 | 2.269V | 2.1 > 2.269: no | 0 | 1010 |

Result: 1010 (decimal 10). Voltage: $10 \times 3.3 / 16 = 2.0625\text{V}$. The error is $2.1 - 2.0625 = 0.0375\text{V}$, which is less than one LSB ($3.3/16 = 0.206\text{V}$).

### Why SAR Is Popular in MCUs

A 12-bit SAR ADC needs exactly 12 comparisons for one result. At a 14 MHz ADC clock (STM32F103), one conversion takes about 1 microsecond. That is fast enough for most sensors, and the circuit is small and uses little power.

The 1 µs uses the shortest sampling time, 1.5 ADC clocks, in which the sample-and-hold capacitor must charge through the source resistance. From a divider or sensor of 10 kΩ or more it does not finish: the reading is low and depends on the channel read before. Choose a longer sampling time (up to 239.5 clocks; the data sheet gives the largest source resistance for each), or, for a slow signal, put 100 nF from the ADC pin to GND.

Other types trade speed for bits: a delta-sigma ADC gives 16 to 24 bits at only 10 to 1000 samples per second.

## Sampling and the Nyquist Theorem

<InArticleAd />


### The Sampling Theorem

An ADC sees the signal only at the instants when it samples, so the samples must come often enough. The Nyquist-Shannon sampling theorem states how often:

> To accurately reconstruct a signal, you must sample at a rate at least **twice** the highest frequency present in the signal.

$$f_{sample} \geq 2 \times f_{max}$$

Both frequencies are in hertz. The limit $2 \times f_{max}$ is called the Nyquist rate.

### Why This Matters

If you sample too slowly, the samples do not show nothing. They show a slower signal that is not there. This is **aliasing**. In a film, a turning wheel can seem to turn slowly backwards for the same reason: the camera takes too few pictures for each turn.

**Example:** You are measuring a 50 Hz power line signal.

- Sampling at 200 Hz: well above the Nyquist rate ($2 \times 50 = 100$ Hz). The samples follow the signal.
- Sampling at 80 Hz: below the Nyquist rate. The samples trace a 30 Hz signal ($|80 - 50| = 30$ Hz). Your measurement shows a wrong frequency, and nothing in the data tells you so.

### Anti-Aliasing Filter

Software cannot remove an alias afterwards, so the high frequencies must be reduced before the ADC. A low-pass filter, which passes slow signals and weakens fast ones, does this. Its cutoff frequency is set below $f_{sample}/2$. A resistor $R$ (in ohms) and a capacitor $C$ (in farads) are often enough:

$$f_{cutoff} = \frac{1}{2\pi RC}$$

**Example:** For a 1 kHz ADC sample rate, the anti-aliasing filter should cut off below 500 Hz. With a 10K resistor: $C = \frac{1}{2\pi \times 10000 \times 500} \approx 32 \text{ nF}$. A 33 nF capacitor would work. The filter weakens signals above the cutoff gradually, so place the cutoff as low as your signal allows.

### Practical Sampling Rates

| Application | Signal Bandwidth | Minimum Sample Rate | Typical Sample Rate |
|-------------|-----------------|--------------------|--------------------|
| Temperature sensor | ~1 Hz | 2 Hz | 10-100 Hz |
| Accelerometer | ~500 Hz | 1 kHz | 1-10 kHz |
| Audio microphone | 20 kHz | 40 kHz | 44.1 kHz or 48 kHz |
| Ultrasonic sensor | 40 kHz | 80 kHz | 200 kHz |

## DAC: Digital-to-Analog Converter

<InArticleAd />


### What a DAC Does

A DAC takes a number and produces a voltage in proportion to it, one step of $V_{ref} / 2^n$ for each count:

$$V_{out} = \frac{\text{Code}}{2^n} \times V_{ref}$$

### R-2R Ladder DAC

Each bit of the code must add its own share of voltage: the top bit a half of $V_{ref}$, the next bit a quarter, and so on. The R-2R ladder does this with only two resistor values, R and 2R, so it is cheap and easy to build.

```text
  D3       D2       D1       D0
  │        │        │        │
 [2R]     [2R]     [2R]     [2R]
  │        │        │        │
  ├──[R]───├──[R]───├──[R]───├──[2R]─→GND
  │
  └──→ Vout (to op-amp buffer)

  D3 contributes Vref/2
  D2 contributes Vref/4
  D1 contributes Vref/8
  D0 contributes Vref/16
```

Each digital input (D0-D3) is connected to $V_{ref}$ (for a 1) or to GND (for a 0). At each joint of the ladder the voltage from the bits further right is divided by two. So D3 (MSB) adds twice as much voltage as D2, which adds twice as much as D1:

$$V_{out} = V_{ref} \times \left(\frac{D_3}{2} + \frac{D_2}{4} + \frac{D_1}{8} + \frac{D_0}{16}\right)$$

For a 4-bit DAC with $V_{ref} = 3.3\text{V}$ and code = 1010 (decimal 10):

$$V_{out} = 3.3 \times \left(\frac{1}{2} + \frac{0}{4} + \frac{1}{8} + \frac{0}{16}\right) = 3.3 \times 0.625 = 2.0625\text{V}$$

### DACs in Microcontrollers

Not all MCUs have a built-in DAC. The ATmega328P and the STM32F103C8 (Blue Pill) have none. The STM32F407 has two 12-bit DACs, and the ESP32 has two 8-bit DACs.

## PWM as a Pseudo-DAC

<InArticleAd />


### Concept

If your MCU has no DAC, PWM (pulse width modulation) with a low-pass filter gives nearly the same result.

A PWM signal switches between 0V and the supply voltage VCC at a fixed frequency. The duty cycle is the fraction of each period for which the signal is high ($t_{on}$ out of $t_{period}$). The average voltage follows it:

$$V_{avg} = V_{CC} \times \frac{t_{on}}{t_{period}} = V_{CC} \times \text{duty cycle}$$

| Duty Cycle | Average Voltage (3.3V VCC) |
|-----------|---------------------------|
| 0% | 0V |
| 25% | 0.825V |
| 50% | 1.65V |
| 75% | 2.475V |
| 100% | 3.3V |

### Filtering PWM to Analog

A raw PWM signal is still a square wave. An RC low-pass filter keeps its average and weakens the fast switching. Think of a water tank fed by a tap that opens and closes quickly: the level follows the average flow, not each opening. The filter is one resistor and one capacitor:

```text
MCU PWM Pin ──[R]──┬──→ Analog Output
                    │
                   [C]
                    │
                   GND
```

Choose the filter cutoff frequency well below the PWM frequency:

- **PWM frequency:** 20 kHz (typical for LED dimming or audio)
- **Filter cutoff:** 200 Hz ($\frac{1}{100}$ of PWM frequency)
- **Calculation:** $R = 10\text{K}$, $C = \frac{1}{2\pi \times 10000 \times 200} = 80 \text{ nF}$ (use 100 nF)

A lower cutoff gives a smoother output, but the output then follows a change of duty cycle more slowly.

### PWM Resolution

A timer makes the PWM by counting its clock, so the high time can change only by one count. The number of duty cycle steps is the timer clock frequency divided by the PWM frequency:

$$\text{PWM steps} = \frac{f_{timer}}{f_{PWM}}$$

**Example:** STM32F103 at 72 MHz, PWM frequency 20 kHz:

$$\text{Steps} = \frac{72{,}000{,}000}{20{,}000} = 3{,}600 \text{ steps}$$

That is about 11.8 bits of resolution ($\log_2 3600 \approx 11.8$), close to a 12-bit DAC. A higher PWM frequency gives fewer steps. A lower one gives more steps but needs a slower filter.

Resolution is not accuracy. With the 10K and 100 nF filter above, the output ripples by about 41 mV peak to peak at 50 % duty, about 45 of those 0.9 mV steps (**check it** with an oscilloscope on AC coupling). For finer output, add a second RC stage and buffer it with an op-amp, since the 10K is in series with any load.

## Practical Exercises

<InArticleAd />


### Exercise 1: ADC Voltage Calculation

Your STM32 has a 12-bit ADC with a 3.3V reference. The ADC reads a value of 2730. What is the input voltage?

<details>
<summary>**Solution**</summary>

$$V_{in} = \frac{2730}{4096} \times 3.3 = 0.6665 \times 3.3 = 2.199\text{V}$$

In C:

```c
float voltage = 2730.0f * 3.3f / 4096.0f;  // 2.199V
```

</details>

### Exercise 2: Resolution Comparison

You need to measure a 0 to 5V signal with a precision of at least 5 mV. What is the minimum ADC resolution required?

<details>
<summary>**Solution**</summary>

The LSB voltage must be less than or equal to 5 mV:

$$\frac{5.0}{2^n} \leq 0.005$$

$$2^n \geq \frac{5.0}{0.005} = 1000$$

$2^{10} = 1024 > 1000$, so a 10-bit ADC is sufficient.

With 10 bits: $V_{LSB} = 5.0 / 1024 = 4.88 \text{ mV}$, which meets the 5 mV requirement.

</details>

### Exercise 3: Sampling Rate

You are measuring vibration on a motor. The vibration frequency range is 10 Hz to 2 kHz. What is the minimum sampling rate? What rate would you choose in practice?

<details>
<summary>**Solution**</summary>

Nyquist rate: $2 \times 2000 = 4000$ Hz minimum.

In practice, use 2.5 to 5 times the Nyquist rate for better signal quality: 10 to 20 kHz. A common choice would be 10 kHz.

You would also need an anti-aliasing filter with a cutoff around 2 to 3 kHz.

</details>

### Exercise 4: PWM DAC Design

You want to generate an analog signal using PWM on an ATmega328P running at 16 MHz (as on an Arduino Uno, which runs from 5V). Using an 8-bit timer (256 levels), what is the PWM frequency? How many voltage levels can you produce?

<details>
<summary>**Solution**</summary>

PWM frequency: $\frac{16{,}000{,}000}{256} = 62{,}500 \text{ Hz} = 62.5 \text{ kHz}$

Voltage levels: 256 (0 to 255). The PWM swings from 0 to the 5V supply, so the step is $5 / 256 = 19.5 \text{ mV}$. (At 3.3V the steps would be $3.3 / 256 = 12.9$ mV, but the data sheet allows 16 MHz only from about 3.8V.)

For filtering, choose a cutoff well below 62.5 kHz. At 625 Hz (1/100 of PWM): $R = 10\text{K}$, $C = \frac{1}{2\pi \times 10000 \times 625} = 25.5 \text{ nF}$ (use 27 nF or 33 nF).

</details>

:::tip[Instrument it]
When you monitor a machine, the sampling rate decides which faults you can see. A bearing fault that makes a tone near 5 kHz needs at least 10 kHz. A slower rate does not only hide the fault. It moves the tone to a wrong frequency, and you read it as something else. Choose the rate from the fault you want to find. Then an [MCU's ADC](/education/sensor-actuator-interfacing-stm32/) can capture it and report what it finds.
:::

## Summary

<InArticleAd />


| Concept | Key Takeaway |
|---------|-------------|
| ADC resolution | More bits give smaller steps. 12-bit is usual in MCUs. |
| LSB voltage | $V_{ref} / 2^n$, the size of one step. The largest code is $2^n - 1$. |
| Quantization error | At most $\pm \frac{1}{2}$ LSB. Only more bits reduce it. |
| SAR ADC | Binary search. Needs $n$ comparisons for $n$ bits. |
| Nyquist theorem | Sample at least $2 \times f_{max}$ to avoid aliasing. |
| R-2R DAC | Simple resistor network for digital-to-analog conversion. |
| PWM as DAC | Timer-generated square wave plus RC filter. Resolution depends on timer frequency. |
