A new sensor returns nothing. A display stays blank. The serial monitor prints random characters. The code looks correct, so the fault is on the wires, and you cannot find it by reading the code again. A microcontroller (MCU) reaches almost every sensor, display and memory chip through one of three serial buses: SPI, I2C or UART. This lesson shows what each one puts on its wires, bit by bit, so that you can read a logic analyzer capture and find the fault. #SPI #I2C #UART

## Parallel vs Serial Communication

### Parallel Buses

A parallel bus sends many bits at the same moment, one per wire, like a road with 32 lanes. The buses inside your MCU (named AHB and APB) are parallel: 32 data lines carry a full word in one clock cycle.

That is fast. But outside the chip, 32 wires need a large connector and much board space, and at high speed each wire disturbs the next one (crosstalk).

### Serial Buses

A serial bus sends the bits one after another over 2 to 4 wires, like a road with one lane. Each clock cycle carries only one bit, so a serial bus uses a fast clock to make up for it. SPI, I2C and UART are all serial.

Sending bits one at a time raises three questions, and each bus answers them in its own way:

- When is a bit valid? SPI and I2C add a clock wire. UART uses an agreed speed.
- Which device is being addressed? SPI uses one select wire per device. I2C sends an address.
- Did the data arrive? Only I2C gives an answer for every byte.

## SPI: Serial Peripheral Interface

<InArticleAd />


### Signal Lines

One device, the master, starts every transfer and makes the clock. In most projects the master is the MCU. The other devices, the slaves, answer. SPI uses four signals:

| Signal | Name | Direction | Function |
|--------|------|-----------|----------|
| SCLK | Serial Clock | Master to slave | Clock signal generated by the master |
| MOSI | Master Out Slave In | Master to slave | Data from master to slave |
| MISO | Master In Slave Out | Slave to master | Data from slave to master |
| CS/SS | Chip Select | Master to slave | Selects one slave. Active-low: the slave is selected when the line is low |

### How SPI Works

SPI is two shift registers connected in a ring. A shift register is a row of flip-flops that moves every bit one place along at each clock pulse.

```text
  Master                         Slave
 ┌──────────┐                   ┌──────────┐
 │ Shift    ├────── MOSI ──────►│ Shift    │
 │ Register │                   │ Register │
 │ (8-bit)  │◄────── MISO ──────┤ (8-bit)  │
 │          ├────── SCLK ──────►│          │
 │          ├─────── CS ───────►│          │
 └──────────┘                   └──────────┘
```

On each clock cycle, one bit leaves the master's shift register on MOSI and one bit enters it from the slave on MISO. After 8 clock cycles, the master and the slave have exchanged one byte. SPI cannot receive without sending: to read a byte, the master must send one, often a byte that means nothing.

### Clock Polarity and Phase (CPOL/CPHA)

A data line must not be read while it changes. So each side changes the data on one clock edge and reads it on the other, and both must agree which edge is which. Two settings fix this, and they give four modes:

- CPOL (clock polarity) is the level of the clock when nothing is sent (0 = low, 1 = high).
- CPHA (clock phase) is the edge on which data is read (0 = first edge after idle, 1 = second edge).

| Mode | CPOL | CPHA | Clock Idle | Data Captured On | Data Changed On |
|------|------|------|-----------|-----------------|-----------------|
| 0 | 0 | 0 | Low | Rising edge | Falling edge |
| 1 | 0 | 1 | Low | Falling edge | Rising edge |
| 2 | 1 | 0 | High | Falling edge | Rising edge |
| 3 | 1 | 1 | High | Rising edge | Falling edge |

Mode 0 is the most common. The data sheet of each device states the mode it needs. With the wrong mode, every bit is read while it changes, and the bytes are wrong.

### SPI Timing Diagram (Mode 0)

```text
CS:   ─┐                                                 ┌─
       └─────────────────────────────────────────────────┘

SCLK:     ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
      ────┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └───

MOSI: ══╡ D7 ╞╡ D6 ╞╡ D5 ╞╡ D4 ╞╡ D3 ╞╡ D2 ╞╡ D1 ╞╡ D0 ╞═══

MISO: ══╡ D7 ╞╡ D6 ╞╡ D5 ╞╡ D4 ╞╡ D3 ╞╡ D2 ╞╡ D1 ╞╡ D0 ╞═══
```

<Steps>
1. Master pulls CS low to select the slave.
2. Master generates 8 clock pulses on SCLK.
3. On each rising edge (Mode 0), both master and slave sample the data line.
4. On each falling edge, both sides set up the next bit.
5. After 8 clocks, one byte has been exchanged in each direction.
6. Master pulls CS high to deselect the slave.
</Steps>

### Multiple Slaves

SCLK, MOSI and MISO are shared by all slaves. Each slave has its own CS line. The master pulls one CS low and keeps all the others high, so only one slave listens and answers.

```text
         Master
        ┌──────┐
  SCLK ─┤      ├─── CS0 ──→ Slave 0
  MOSI ─┤      ├─── CS1 ──→ Slave 1
  MISO ─┤      ├─── CS2 ──→ Slave 2
        └──────┘
```

So SPI needs one more MCU pin for each slave. With many slaves, a decoder (for example a 3-to-8 decoder) can make 8 CS signals from 3 pins.

## I2C: Inter-Integrated Circuit

<InArticleAd />


### Signal Lines

I2C uses only two wires for any number of devices:

| Signal | Name | Function |
|--------|------|----------|
| SCL | Serial Clock | Clock signal (driven by master) |
| SDA | Serial Data | Bidirectional data line (shared) |

If many devices share one wire, two of them could drive it at the same time, one high and one low. That is a short circuit. I2C prevents it with open-drain drivers: a device can only pull the line low, or let it go. A pull-up resistor (typically 4.7 kΩ to the supply, VCC) pulls the line high when every device has let it go.

Think of a door held open by a spring. Any person can push it closed, and it is open only when nobody pushes.

The spring sets the speed. The resistor charges the capacitance of the wires and the device pins, so the line rises slowly, and the bus allows at most 1000 ns of rise time in Standard mode and 300 ns in Fast mode. With 4.7 kΩ that is reached at about 250 pF and 75 pF of total capacitance. A cable of a metre or two plus a few modules is near 100 pF, so 400 kHz over a cable usually needs a smaller resistor (2.2 kΩ allows about 160 pF) or a lower clock.

### I2C Bus with Multiple Devices

```text
        VCC
         │
       [4.7K]
         │
  SDA ───┴────┬───────────┬───────────┬───────────┬────
              │           │           │           │
         ┌────┴───┐  ┌────┴───┐  ┌────┴───┐  ┌────┴───┐
         │ Master │  │ BME280 │  │SSD1306 │  │ DS3231 │
         │ (MCU)  │  │  0x76  │  │  0x3C  │  │  0x68  │
         └────┬───┘  └────┬───┘  └────┬───┘  └────┬───┘
              │           │           │           │
  SCL ───┬────┴───────────┴───────────┴───────────┴────
         │
       [4.7K]
         │
        VCC
```

### I2C Addressing

There is no select wire, so the master names the slave it wants. Each slave has a 7-bit address, fixed by the maker of the chip. The master sends the address at the start of each transfer, and only that slave answers. Two devices with the same address cannot share a bus.

| Device | Typical Address |
|--------|----------------|
| BME280 sensor | 0x76 or 0x77 |
| SSD1306 OLED | 0x3C or 0x3D |
| DS3231 RTC | 0x68 |
| EEPROM (24C256) | 0x50-0x57 |

### I2C Protocol: Write Transaction

A complete I2C write of one data byte puts 18 bits on SDA, each with one clock pulse on SCL:

```text
SDA ─┐ ┌─────────┬───┬───┬─────────┬───┐ ┌─
     └─┤ A6...A0 │R/W│ACK│ D7...D0 │ACK├─┘
       └─────────┴───┴───┴─────────┴───┘
  START  address   0  slave  data  slave STOP
          7 bits      low   8 bits  low
```

<Steps>
1. **START condition:** Master pulls SDA low while SCL is high. This tells all slaves to listen.
2. **Address byte:** Master sends the 7-bit slave address and then the R/W bit (0 = write, 1 = read). The most significant bit (MSB) goes first.
3. **ACK from slave:** For the 9th clock pulse the master lets SDA go, and the addressed slave pulls it low. This is the acknowledge (ACK). If no slave has that address, nothing pulls SDA low and it stays high (NACK). The master then knows the transfer failed.
4. **Data byte:** Master sends 8 data bits, MSB first.
5. **ACK from slave:** Slave acknowledges the data byte in the same way.
6. **STOP condition:** Master releases SDA while SCL is high.
</Steps>

During data bits, SDA changes only while SCL is low. A change of SDA while SCL is high can therefore mean only START or STOP.

### I2C Clock Stretching

A slave that needs more time can hold SCL low. The master must wait until SCL goes high before it continues. This is called clock stretching, and it is why SCL is also open-drain.

### I2C Speed Modes

| Mode | Maximum Clock |
|------|--------------|
| Standard | 100 kHz |
| Fast | 400 kHz |
| Fast-Plus | 1 MHz |
| High-Speed | 3.4 MHz |

Most projects use Standard or Fast mode.

## UART: Universal Asynchronous Receiver/Transmitter

<InArticleAd />


### Signal Lines

UART connects two devices with one data line in each direction and no clock:

| Signal | Direction | Function |
|--------|-----------|----------|
| TX | Out of this device | Data output |
| RX | Into this device | Data input |
| GND | Common | Shared ground reference |

There is no clock wire, so both sides must be set to the same speed before they start. The speed is the baud rate, in bits per second. "Asynchronous" means this: no shared clock.

### UART TX/RX Connection

```text
  Device A              Device B
  ┌────────┐            ┌────────┐
  │     TX ├───────────→│ RX     │
  │        │            │        │
  │     RX │◄───────────┤ TX     │
  │        │            │        │
  │    GND ├────────────┤ GND    │
  └────────┘            └────────┘
```

The TX of one device goes to the RX of the other. A voltage is always measured against a reference, so the two grounds must also be connected.

### UART Frame Format

The line rests high. Each byte travels in a frame that tells the receiver where the byte starts and ends:

```text
Idle ──┐   ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬─────── Idle
       └───┤D0 │D1 │D2 │D3 │D4 │D5 │D6 │D7 │(P)├───────
       Start  8 data bits (LSB first)      Parity  Stop
       bit                                 (opt.)  bit(s)
```

| Component | Bits | Function |
|-----------|------|----------|
| Start bit | 1 | Always 0 (low). Signals the beginning of a frame. |
| Data bits | 5-9 (usually 8) | The data, least significant bit (LSB) first. |
| Parity bit | 0-1 | Optional. One extra bit that lets the receiver detect a single wrong bit. |
| Stop bit(s) | 1-2 | Always 1 (high). Signals the end of the frame. |

### Baud Rate

One bit lasts 1 / baud rate seconds. At 9600 baud that is 1 / 9600 s = 104.2 µs. Common rates:

| Baud Rate | Bit Period | Byte Period (8N1) |
|-----------|------------|-------------------|
| 9600 | 104.2 us | 1.04 ms |
| 115200 | 8.68 us | 86.8 us |
| 921600 | 1.09 us | 10.9 us |

"8N1" means 8 data bits, no parity, 1 stop bit. It is the most common setting. Each byte takes 10 bit periods (1 start + 8 data + 1 stop).

### How the Receiver Synchronizes

The receiver has no clock from the sender, so it starts its own timer at the start bit:

<Steps>
1. The line is idle (high).
2. The receiver detects a falling edge (start bit).
3. The receiver waits half a bit period to sample the middle of the start bit, confirming it is still low.
4. The receiver then samples at one-bit-period intervals to read each data bit.
5. After the last data bit (and optional parity), the receiver checks for the stop bit (high).
6. The receiver returns to waiting for the next start bit.
</Steps>

The two timers are never exactly equal, and the error adds up through the frame. The stop bit is read 9.5 bit periods after the start edge. If the two rates differ by 5%, that reading is 9.5 × 5% = 0.475 of a bit late, at the very edge of the bit. So the two baud rates must match within about 2-3%. Each new start bit sets the error back to zero.

### UART vs RS-232 vs TTL

| Standard | Voltage Levels | Connector |
|----------|---------------|-----------|
| TTL UART | 0V (low) and 3.3V or 5V (high) | Pin headers |
| RS-232 | -12V (high) and +12V (low) | DB-9 connector |
| RS-485 | Differential pair | Screw terminals |

These standards carry the same frame at different voltages. MCU UART pins work at TTL levels. An RS-232 port uses up to ±12V and will damage an MCU pin, so it needs a level converter like the MAX232. To reach a PC, use a USB-to-TTL serial adapter (like the FTDI FT232 or CH340).

## Comparing SPI, I2C, and UART

<InArticleAd />


| Feature | SPI | I2C | UART |
|---------|-----|-----|------|
| Wires | 3 + 1 per slave | 2 (shared) | 2 (point-to-point) |
| Clock | Yes (master) | Yes (master) | No (asynchronous) |
| Speed | Up to 50 MHz | Up to 3.4 MHz | Up to ~1 Mbaud |
| Duplex | Full duplex | Half duplex | Full duplex |
| Addressing | CS pin per slave | 7-bit address | None (point-to-point) |
| Acknowledgment | None (by default) | ACK/NACK per byte | None (or parity bit) |
| Typical use | Fast peripherals (display, Flash, ADC) | Sensors, RTCs, EEPROMs | Debug console, GPS, Bluetooth modules |
| Pin count for 4 slaves | 7 (SCLK, MOSI, MISO, 4xCS) | 2 (SCL, SDA) | 8 (4 TX + 4 RX pairs) |

### When to Use Which

## Practical: Observe Serial Signals

<InArticleAd />


### Using a Logic Analyzer

A logic analyzer records digital signals and shows them as timing diagrams like the ones above. Low-cost USB logic analyzers can also decode SPI, I2C and UART: they print the value of each byte over the waveform.

<Steps>
1. **Connect probes** to the signal lines (SCLK, MOSI, MISO, CS for SPI; SCL, SDA for I2C; TX for UART). Always connect the analyzer's GND to the circuit's GND.

2. **Set the sample rate** to at least 4 times the bus clock frequency. For SPI at 1 MHz, sample at 4 MHz or higher.

3. **Trigger** on the CS falling edge (SPI), START condition (I2C), or TX falling edge (UART).

4. **Capture** one transfer.

5. **Enable protocol decoding** to see addresses, data values and ACK/NACK on the waveform.

6. **Check it** against numbers you can work out before you look. Measure one UART bit with the cursors: at 115200 baud it must be 8.68 µs, and more than about 2 % away means a wrong clock setting. For I2C, the first byte of a write to address 0x50 must decode as 0xA0, followed by an ACK. If the decoder shows something else, trust the measured timing first, then check the decoder settings (baud rate, bit order, SPI mode).
</Steps>

### What to Look For

**SPI problems:**
- Clock polarity mismatch (CPOL): data looks shifted or garbled
- CS not going low: slave ignores all data
- MISO stuck high: slave not responding (wrong CS, slave not powered, or wrong SPI mode)

**I2C problems:**
- NACK after address: wrong address, slave not powered, or missing pull-up resistors
- SDA stuck low: slave holding the bus. This happens when the MCU resets in the middle of a read and the slave is still sending a 0. It has no reset pin, so at start-up send up to 9 clock pulses on SCL (as plain GPIO) until SDA goes high, then a STOP. Power cycling the slave also works.
- Missing pull-up resistors: signals do not reach VCC, causing intermittent failures

**UART problems:**
- Baud rate mismatch: data appears as garbage characters
- TX/RX swapped: no data in either direction
- Missing ground connection: no data or random noise

## Exercises

<InArticleAd />


### Exercise 1: SPI Byte Exchange

A master sends `0xA5` to a slave via SPI Mode 0, MSB first. Draw the sequence of bits on MOSI for all 8 clock cycles.

<details>
<summary>**Solution**</summary>

`0xA5` = `10100101` in binary.

| Clock Cycle | SCLK Rising Edge | MOSI |
|------------|-------------------|------|
| 1 | First | 1 (bit 7) |
| 2 | Second | 0 (bit 6) |
| 3 | Third | 1 (bit 5) |
| 4 | Fourth | 0 (bit 4) |
| 5 | Fifth | 0 (bit 3) |
| 6 | Sixth | 1 (bit 2) |
| 7 | Seventh | 0 (bit 1) |
| 8 | Eighth | 1 (bit 0) |

Each bit is sampled on the rising edge and changed on the falling edge.

</details>

### Exercise 2: I2C Address Calculation

You want to write to a device at address `0x50`. What is the full first byte sent on the bus (including the R/W bit) for a write operation? What about for a read?

<details>
<summary>**Solution**</summary>

The first byte is the 7-bit address shifted left by 1, with the R/W bit in bit 0.

Write: `(0x50 << 1) | 0 = 0xA0` (binary: `10100000`)

Read: `(0x50 << 1) | 1 = 0xA1` (binary: `10100001`)

In C:

```c
uint8_t write_addr = (0x50 << 1);       // 0xA0
uint8_t read_addr  = (0x50 << 1) | 1;   // 0xA1
```

</details>

### Exercise 3: UART Timing

At 115200 baud, how long does it take to transmit the string "Hello" (5 characters)? Assume 8N1 framing.

<details>
<summary>**Solution**</summary>

Each character requires 10 bits (1 start + 8 data + 1 stop).

5 characters = 50 bits.

Time per bit = $\frac{1}{115200}\text{ s} = 8.68\,\mu\text{s}$

Total time = $50 \times 8.68\,\mu\text{s} = 434\,\mu\text{s} \approx 0.43 \text{ ms}$

</details>

:::tip[Instrument it]
A logic analyzer shows the bus on the bench. In a deployed device, the microcontroller itself can count what happens on the bus: how often a sensor answers, how often a device gives a NACK, how long a transfer takes. An [ESP32 or STM32](/education/sensor-actuator-interfacing-stm32/) on the bus can report these counts to [a broker you run](/education/iot-systems/mqtt-broker-setup-secure-connection/). A failing sensor or a weak pull-up then appears as a rising error count before the device stops working.
:::

## Summary

<InArticleAd />


| Protocol | Signals | Clock | Speed | Best For |
|----------|---------|-------|-------|----------|
| SPI | SCLK, MOSI, MISO, CS | Synchronous (master) | Up to 50 MHz | High-speed peripherals |
| I2C | SCL, SDA | Synchronous (master) | Up to 3.4 MHz | Multiple low-speed devices |
| UART | TX, RX | Asynchronous | Up to ~1 Mbaud | Point-to-point, debug console |

All three buses carry numbers. The ADC and the DAC turn a real voltage into such a number, and back.
